# Neural Network-Based Contextual Token Classification for C Programs

## Overview

This project implements a neural network-based token classification system for C source code. It uses a character-level and contextual Bidirectional Long Short-Term Memory (BiLSTM) architecture to classify lexical tokens, together with a Streamlit dashboard for inspecting token predictions, comparing lexical analysis methods, examining parser diagnostics, and visualizing abstract syntax trees (ASTs).

Pygments identifies token boundaries and provides reference labels for supervised learning and comparison. The trained PyTorch model predicts token categories using character patterns and neighboring token context. Syntax-tree generation and parser diagnostics are separate from neural token classification.

## Token Categories

| Category | Examples |
|---|---|
| **KEYWORD** | `int`, `return`, `if`, `while` |
| **IDENTIFIER** | `main`, `count`, `total` |
| **OPERATOR** | `=`, `+`, `*`, `>=` |
| **LITERAL** | `42`, `3.14`, `"Hello"` |
| **DELIMITER** | `(`, `)`, `{`, `}`, `;`, `,` |

## Architecture and Workflow

1. **Lexical tokenization:** Pygments extracts tokens from C source code and supplies reference categories.
2. **Character encoding:** Tokens are converted into fixed-length character-ID sequences using a character vocabulary.
3. **Character-level representation:** A BiLSTM processes characters within each token.
4. **Contextual representation:** A second BiLSTM processes token representations in sequence to capture surrounding context.
5. **Token classification:** A classification layer predicts a token category and a confidence score.
6. **Analysis and visualization:** The Streamlit interface displays predictions, reference comparisons, evaluation results, and parser-generated syntax structures.

The neural model classifies tokens produced by the lexical tokenizer; it does not independently discover token boundaries or replace the C parser.

## Application Modules

### 1. Token Classifier

Classifies tokens in C source code into five lexical categories. The dashboard displays token-level predictions and confidence scores, highlighted code, token distributions, and reference-label comparisons.

### 2. Smart Token Error Detector

Supports inspection of token-level anomalies and compiler-related diagnostics. Lexical classification and syntactic validity are distinct: errors such as a missing semicolon require parsing or syntax checking rather than token classification alone.

### 3. Model Comparison Lab

Compares the neural BiLSTM classifier with the Pygments reference lexer. The comparison includes inference latency, token-processing throughput, and agreement between predicted and reference labels. Agreement measures concordance with the reference lexer, not independent proof of correctness.

### 4. Syntax Tree Visualizer

Parses C code and displays an abstract syntax tree with connected parent–child nodes. The visualization represents language constructs such as function definitions, declarations, expressions, conditions, and return statements. Source line and column positions can be displayed as diagnostic metadata where supported.

The syntax tree is generated by the C parsing component, not by the BiLSTM token classifier.

### 5. Model Evaluation & Metrics

Presents model-evaluation information, including classification metrics and visualizations generated from the evaluation pipeline. Metrics can include accuracy, precision, recall, F1-score, and confusion-matrix results.

## Installation

### Prerequisites

- Python 3.12
- Git (for repository management)
- Graphviz `dot` executable for optional SVG rendering

### 1. Create a virtual environment

Open a terminal in the project root. On Windows PowerShell:

```powershell
python -m venv .venv
.\.venv\Scripts\Activate.ps1
```

### 2. Install dependencies

```powershell
python -m pip install -r requirements.txt
```

### 3. Run the dashboard

```powershell
python -m streamlit run app.py
```

Open the local address displayed by Streamlit (typically `http://localhost:8501`).

A compatible saved checkpoint in `artifacts/model.pt` is required for inference without retraining.

## Model Training

To train the model using the available C training data:

```powershell
python -m src.train --epochs 30 --batch_size 8 --lr 0.003
```

The training pipeline uses training and validation data and saves model artifacts and evaluation outputs. A held-out test set is used for final evaluation when available.

## Testing

Run the automated tests from the project root:

```powershell
python -m pytest -v
```

## Evaluation

The classifier is evaluated against reference token labels. Relevant measures include:

- **Accuracy:** Proportion of correctly classified tokens.
- **Precision:** Proportion of predicted tokens in a class that match the reference class.
- **Recall:** Proportion of reference tokens in a class that are correctly identified.
- **F1-score:** Harmonic mean of precision and recall.
- **Confusion matrix:** Distribution of correct predictions and misclassifications by class.

Evaluation results depend on the training dataset, held-out examples, and Pygments-derived reference labels. The Model Comparison Lab additionally reports execution-time and agreement measurements for selected source programs.

## Scope and Limitations

The system focuses on **token classification**, not full compilation. Pygments supplies token boundaries and training/reference labels, while the neural network predicts token classes. Parsing and AST generation are implemented separately. A missing token or an invalid statement is not necessarily detectable from classification confidence alone.

Model performance may vary for unfamiliar C programs, uncommon identifiers, preprocessing constructs, and code patterns not adequately represented in the training data. Reported agreement with a reference lexer should not be interpreted as universal classification accuracy.
